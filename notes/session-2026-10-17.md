## Blender add-on

- **Copy Keyframes** (`kinetic_forge.copy_keyframes`): copies every animated mesh's keyframes to the clipboard. It's greyed out until a mesh has location or rotation keys. The exporter moved from the test script into `blender/kinetic_forge/export.py`, which `run_fracture.py` now also uses.
  - Objects keyed on only some axes no longer crash the export. The missing axes use the object's current value.
  - Objects using quaternion or axis-angle rotation are skipped.
- **Bake to Keyframes** bakes from the timeline's Start to End, or the preview range when that's on. It used to use the simulation cache's range.
  - Making it bake the simulation cache first was tried, then reverted at your request.
- Blender's own bake-to-keyframes removes the rigid bodies afterwards, and deletes keyframes that don't change anything. That's why a piece that has stopped moving drops out of later frames in the export.

## Uploading with Roblox's Blender plugin

- The README now covers installing it, signing in, and uploading a fractured collection on frame 1.
- **Untick Bake Animation** in its add-on preferences. With it on, uploading a collection freezes Blender, because the plugin exports every piece's animation onto every other piece. The motion isn't needed anyway, since Kinetic Forge rigs and animates the pieces in Roblox.
- A `403 PERMISSION_DENIED` on upload means the collection has a **Roblox Package ID** for an asset the chosen creator doesn't own. Delete the property to upload as a new asset.
- Not yet checked: whether the plugin's export (forward -Z, up Y, scale 0.01) matches the axis mapping and scale `KeyframeData` now expects. `CheckRig` will show it.

## Rojo and reloading

- **Rokit and Rojo 7.7.1** are installed, and Rojo is pinned in `rokit.toml`.
- **`default.project.json`** builds the plugin. Rojo can't detect `init.legacy.luau` by name, so the main script is set explicitly and its child modules are listed by hand.
- **`debug.project.json`** syncs into `PluginDebugService > user_KineticForge.rbxm`. Studio only allows `Plugin` instances there, and only Studio can create those, so the installed copy has to exist first (**Build plugin** task).
- **VS Code tasks:**
  - **Watch plugin** runs `rojo serve` and the sourcemap watcher, and starts when the folder opens.
  - **Build plugin** writes `KineticForge.rbxm`.
  - Both add Rokit's folder to the PATH themselves.
- **Self-reloading:** Studio doesn't restart a debug plugin when its code changes, so the plugin does it itself:
  - `init.legacy.luau` creates the toolbar, button and widget once, watches the modules' code, and on a change re-requires fresh copies of the modules.
  - The plugin's own code moved into `App.luau`, which puts everything it makes in its Trove so a reload can remove it.
  - This works. Edits to `init.legacy.luau` itself still need a manual reload.
